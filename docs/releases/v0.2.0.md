# ToxicJoin v0.2.0

This release replaces the retired static hosting path with one Render-hosted application and
introduces a complete, responsive redesign of the public product interface.

## Product changes

- New interface architecture and visual system, designed from a blank canvas.
- Clear product path: overview, public deployment status, live console, decision lab, and evidence.
- Responsive desktop and mobile layouts with reduced-motion support and visible focus states.
- Render is the only public deployment target and the UI uses its real API path.
- An unavailable API now fails explicitly with a reconnect action; no static data fallback is used.
- Legacy hosting configuration, static assets, verification workflow, and supply-chain naming are removed.

## Verified release surface

The attached Release Manifest binds CI, benchmark, PPMC, supply-chain, container, security,
portability, Live DataHub, production browser E2E, topology, and durable evidence retention to the
exact release commit.

The release remains truthful about current boundaries:

- canonical disclosure topology is `SINGLE_NODE`;
- multi-replica stateful privacy support is not claimed;
- PostgreSQL is not canonical product behavior;
- the [Current Public Demo](https://toxicjoin-public-demo.onrender.com/) uses a synthetic fixture
  through the real protected execution path and contains no institutional data or credentials;
- Render runtime state is temporary and may reset after sleep or restart, so it is not a durable
  audit record;
- Live DataHub is established separately by Exact-SHA CI evidence, not by the public Render service;
- video publication and Devpost synchronization are not claimed by this release.
